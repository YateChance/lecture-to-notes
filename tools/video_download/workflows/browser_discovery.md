# 浏览器发现与下载交接

执行者：当前Codex，通过已授权且可用的浏览器工具操作。先查看实际页面，不凭猜测拼接媒体URL。浏览器工具的具体API以当前工具文档为准，不把会话中的tab ID写死。

## 通用流程

1. 打开用户给出的页面或认领已经打开的对应标签页。核对标题、课程、日期和所需的视频流。
2. 若有正常“下载/导出”入口，优先使用。需要登录时使用正常登录流程；遇到需用户完成的认证步骤则交接。
3. 若无入口但能正常播放，只读检查页面实际存在的媒体元素，例如`video.currentSrc`、`src`和`duration`。不读取Cookie、密码或浏览器存储中的凭据。
4. 可尝试浏览器工具的媒体下载能力。超时只说明该路径未完成，不代表整个视频无法下载。
5. 根据实际发现的来源选择方式：
   - HTTP(S)视频文件：填写私有请求，使用direct_http。
   - 必须依赖浏览器会话才能下载的媒体：继续使用浏览器正常下载，之后local_file导入，不把浏览器凭据搬到命令行。
   - blob：保留页面，寻找原生下载或平台导出；blob字符串不是可供curl访问的URL。
   - HLS/DASH：明确交给流媒体适配器或合适下载器；得到本地视频后导入。
   - 受保护或无法访问的内容：说明具体阻碍，改用平台允许的导出或用户已有文件，不承诺技术绕过。
6. 核对下载结果的实际时长、视频轨和来源角色，再登记00_sources；不要把HTTP 200登录页视为成功。

一个只读媒体检查的逻辑示例是：

```javascript
// 仅在当前浏览器工具支持且页面确实存在video元素时使用。
await tab.playwright.locator('video').evaluateAll(elements =>
  elements.map(element => ({
    src: element.getAttribute('src'),
    currentSrc: element.currentSrc,
    duration: element.duration
  }))
);
```

若返回临时签名地址，直接写入 `outputs/.download_requests/` 的私有请求文件，不写进profile、代码、README或公开日志。

## 本次北航课堂的已验证轨迹

- 页面类型：`classroom.msa.buaa.edu.cn/livingroom`课程回放。
- 核对内容：动力系统，2026年9月18日，第2周；当前选中教师流。页面另有PPT视频，不能混为同一份。
- 正常播放器中的video元素暴露了 `resource.msa.buaa.edu.cn` 的HTTP MP4媒体源，带有效期相关查询参数。
- 浏览器媒体下载接口在60秒内未完成，因此转为下载当前播放器实际使用的MP4地址。
- 命令行HTTP下载成功；文件约2.45 GB，时长约02:28:32，视频为1080p H.264，含AAC音轨。随后验证并归档。
- 签名地址不作为固定配置保存。下次课程必须重新从实际页面发现，不复用上次签名或盲猜其他课程资源路径。

这条轨迹证明该案例可行，不说明该域名下每个视频都可采用完全相同的方法。
