# 增加一种下载方式

先区分是“发现步骤不同”还是“传输协议不同”。

## 仅站点页面不同

在profiles增加JSON，说明域名、正常下载路径、播放器线索、视频流角色和失效后的处理方式。仍输出同样的请求字段，不复制direct_http代码，不保存实际登录信息或临时签名。

## 需要新传输后端

1. 在adapters增加模块，实现 `fetch(request, part, state_path, state) -> transport_metadata`。
2. 在 `adapters/__init__.py` 显式注册名称。
3. 后端只负责将数据写入给定part文件；不直接写最终视频、不绕过common中的验证和来源登记。
4. 新增后端字段应校验并写入文档。敏感URL、Cookie和认证信息不能进入完成回执或公开日志。
5. 流媒体后端需要独立处理清单、音视频轨、合并、中断和协议限制；不能用“curl把m3u8保存成mp4”代替实现。受保护内容不在解密范围内。
6. 以本地或明确可下载的公开样例验证成功、失败、恢复和来源记录，明确平台版本与能力边界。

当前已注册的后端只有direct_http和local_file；本文件是扩展协议，不代表HLS、DASH或yt-dlp后端已经实现。
